# Live Map Flight Aids Design

## Goal

Add optional grid and foreground location overlays to every signed-in map so a pilot can see their current position, recent trail, and the claim-cell boundaries around them while flying. The overlays aid navigation without changing claim processing, competition scoring, map periods, or pilot selection.

## Scope

The feature adds three small MapLibre controls to Global, Personal, and Arena maps:

- Grid toggles neutral claim-cell outlines.
- Location starts, stops, and resumes foreground position following.
- Clear Trail appears only when a stored trail exists and deletes that trail.

The feature does not record or upload a flight, create server-side trail data, claim cells in real time, track location reliably in the background, change the active competition period, or alter existing territory and coverage layers.

Both grid and location controls are available in desktop and mobile layouts.

## Architecture

Grid geometry is generated by the server from the same configured cell size and EPSG:6933 grid used by claim processing. This prevents browser-side projection math from drifting away from the cells that GlideHero actually scores.

The server exposes two authenticated read paths:

- A viewport path generates cells intersecting the visible Global or Personal viewport. The path validates the geographic bounds and enforces a maximum area or cell count.
- An Arena path returns only the stored `launch_area_cells` belonging to the requested Arena and configured cell size.

The browser adds focused shared modules for grid behavior, location behavior, trail storage/rendering, and a small initializer that connects them to a MapLibre map. Global, Personal, and Arena controllers call the initializer after constructing their maps. Existing coverage, territory, leaderboard, period, and stats modules remain responsible for their current behavior.

No database schema change or data migration is required.

## Grid Overlay

### Shared behavior

The grid button starts off after every page load. Its state is not stored across navigation or reloads. Turning it on adds cell outlines only, with no fill and no claimed/unclaimed coloring. Turning it off hides the grid without changing any underlying map source.

The grid is an independent overlay. It does not switch All Time to Current Month, select the signed-in pilot, modify existing coverage, or otherwise change the current map state.

The GeoJSON cells retain stable `cellSize`, `x`, and `y` properties for tests and future map interactions, although this feature does not make grid-only cells interactive.

### Global and Personal

Global and Personal request the cells intersecting the current map viewport only after reaching a practical minimum zoom. Below that threshold, the browser makes no request and the grid control reports `Zoom in to view grid.`

While the grid is enabled, `moveend` refreshes the visible grid after panning or zooming. Requests use the existing latest-request cancellation pattern so stale responses cannot replace newer viewport data. The server independently enforces its response-size limit rather than trusting the browser zoom check.

### Arena

Arena returns only the configured cells stored for that Arena. Because this is a finite set, Arena grid display has no minimum-zoom restriction. The browser fetches the Arena grid on the first toggle and reuses it for the lifetime of the page.

## Live Location

The location button starts off after every page load or navigation. A user gesture starts `navigator.geolocation.watchPosition` with high accuracy requested. The browser does not attempt to restore active tracking automatically after a reload or navigation.

Accepted fixes with reported accuracy of 100 meters or better update a simple MapLibre accuracy dot and append a point to the active trail segment. Fixes worse than 100 meters are ignored for both display and trail storage so they cannot create large misleading jumps.

While follow mode is active, accepted fixes recenter the map on the pilot. Manually panning the map pauses only follow mode; GPS watching and trail collection remain active. Tapping the location button while panned resumes following. Tapping it while actively following stops the geolocation watch and closes the active trail segment. Restarting tracking opens a new segment.

Permission denial, unsupported geolocation, timeouts, and unavailable positions leave the stored trail intact. They return the control to a non-following state and show a concise map-local status message.

## Trail Storage and Rendering

There is one browser-local trail shared by Global, Personal, and Arena maps. It is stored under one versioned `localStorage` key as a collection of ordered segments. Each stored point contains only the coordinates and timing needed to render and separate the trail; no trail is sent to the server.

The browser restores and renders all valid stored segments when any map loads. Tracking off/on, page backgrounding, and page reload or navigation create segment boundaries. The browser also uses timestamps as a defensive fallback when visibility events are unavailable or delayed. Missing background intervals are never connected by a straight line.

When the page becomes hidden, current web platform behavior cannot deliver dependable position updates. The current segment is closed. If tracking was enabled and the page becomes visible again, foreground tracking continues when the browser permits it and the next accepted fix starts a new segment.

Clear Trail appears only when at least one stored or in-memory point exists. Activating it removes all stored segments, clears the rendered trail immediately, and hides the control. It does not stop an active location watch; the next accepted fix begins a new trail.

Stored data is parsed defensively. Corrupt or unsupported trail payloads are discarded without preventing the map from loading. If the browser storage quota is exhausted or storage becomes unavailable, the current page retains and renders new points in memory while reporting that those points cannot be persisted.

## API Contracts

The implementation adds authenticated GeoJSON endpoints equivalent to:

- `GET /v1/grid?west=...&south=...&east=...&north=...` for Global and Personal.
- `GET /v1/arenas/:sourceId/grid` for Arena.

The viewport endpoint accepts the existing validated viewport-bounds shape, including the established antimeridian handling used by map queries. Invalid bounds return `400`. Requests exceeding the server limit return a client-actionable response that tells the browser to ask the user to zoom in.

The Arena endpoint validates the source ID, returns `404` for an unknown Arena, and queries only rows matching the configured claim cell size. Both endpoints return a GeoJSON `FeatureCollection` of Polygon cells with `cellSize`, `x`, and `y` properties.

Anonymous requests return `401` without querying grid data.

## Browser Composition

The shared initializer receives the MapLibre map instance, map element, fetch implementation, and optional Arena source ID. It installs the grid, location, trail, and conditional clear controls without owning the existing map lifecycle.

The modules have the following boundaries:

- Grid API utilities build canonical viewport and Arena URLs.
- Grid overlay owns the neutral GeoJSON source/layer, toggle state, zoom gating, and refresh requests.
- Trail storage validates, restores, appends, segments, clears, and persists the versioned payload.
- Location tracker owns geolocation watch state, accuracy filtering, the accuracy dot, follow mode, manual-pan handling, and visibility transitions.
- Trail renderer converts stored segments into line GeoJSON and keeps the shared trail source current.
- The flight-aids initializer wires those units to a map and provides map-local status reporting.

The disabled Personal map-action placeholders are removed. All three maps use the same real controls and accessible labels.

## Error Handling

Grid failures never remove or disable existing map functionality. A failed request leaves the prior grid data hidden or unchanged as appropriate and reports a retryable map-local message. A later toggle or viewport change can retry.

Location failures preserve the trail and do not affect the grid. Permission denial does not repeatedly prompt without another user gesture. GPS loss closes the current segment before a later successful restart.

The clear action updates memory, storage, MapLibre data, and control visibility as one operation. Storage removal failure is reported, and the control remains available if persisted data may still exist.

## Testing

Unit tests cover:

- Canonical viewport and Arena grid URLs.
- Grid control on/off state, neutral layer creation, Arena caching, minimum-zoom behavior, move refreshes, and stale-request protection.
- Location start, stop, resume-follow, manual-pan, visibility, and error transitions.
- Rejection of fixes worse than 100-meter accuracy.
- Trail segment creation across stop/start, background/foreground, reload, and timestamp gaps.
- Versioned storage restoration, corrupt-data recovery, quota failure, shared cross-map rendering, and clearing.
- Accuracy-dot updates and conditional Clear Trail visibility.
- Global, Personal, and Arena controller integration with the shared initializer.

Integration tests cover:

- Authentication and validation for both grid endpoints.
- Viewport cells aligned with the configured PostGIS grid.
- Antimeridian-safe viewport behavior.
- Server response-size enforcement.
- Arena results limited to the Arena's stored cells at the configured cell size.
- Unknown Arena handling.

Existing map style, competition coverage, dashboard controller, responsive layout, renderer, router, and web-flow suites remain passing.

Manual browser verification covers desktop and mobile permission allow/deny, accepted and rejected accuracy fixes, follow and manual pan behavior, background/foreground gaps, stop/restart segmentation, reload persistence, cross-map trail reuse, Clear Trail, Global and Personal zoom gating, and Arena-only grid membership.

## Success Criteria

- A pilot can toggle neutral claim-cell outlines on every map.
- Arena outlines always match its finite stored cell membership.
- Global and Personal grids render only at a safe zoom and match claim-processing coordinates.
- A pilot can start foreground tracking and see a simple accuracy dot plus a temporary local trail.
- Manual panning pauses following without pausing trail collection.
- Background gaps and stop/restart gaps are visibly separate segments.
- One trail survives navigation and browser restarts until explicitly cleared.
- No trail is uploaded, scored, or treated as a flight.
- Existing map state and competition behavior remain unchanged beneath the optional overlays.
